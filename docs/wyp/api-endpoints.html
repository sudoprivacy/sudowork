两台服务器的分界（先读这条）

🔑 个人模式与企业模式共用 /api/v1/* 路径方案，但打的是两台不同的服务器：
  • 个人模式 → 数牍中控 SaaS 服务器 https://sudowork-server.sudoprivacy.com（硬编码，sudoworkServer.getConfig 恒返回此地址，src/common/sudoworkServer.ts）
  • 企业模式 → 客户私有部署的 MOSS 服务器 eeclaw.serverUrl / mossServerUrl（用户配置，无默认值）
判断归属的依据：用 ipcBridge.sudoworkServer.getConfig().baseUrl 的 = 中控；用 ConfigStorage.get('eeclaw.serverUrl') / ProcessConfig mossServerUrl 的 = MOSS。
🧩 注意区分本地账号：这里列的认证接口（手机号 / 企业账号）才是"产品登录"，身份存在 localStorage + config.txt。本地 SQLite users 表是另一套——只用于 WebUI 浏览器门禁（admin 密码）和本地数据归属（conversations.user_id），不存产品账号、登录注册也不写它。详见 本地数据库详解 · users 表。

个人 / 企业 接口分栏对照

个人模式

中控 https://sudowork-server.sudoprivacy.com
认证 / 注册 AuthContext.tsx · login/index.tsx
  • POST/api/v1/auth/send-code发送手机短信验证码
  • POST/api/v1/auth/login手机号+验证码登录；返回 token + sudorouter_key/model_service_url（模型代理密钥）
  • POST/api/v1/auth/register新用户注册（register_token + 昵称 + 邀请码）
  • POST/api/v1/auth/refresh刷新 access_token
  • POST/api/v1/auth/logout注销
用户 / 仪表盘 DashboardStatsContext · useModelUsageStats · UserProfile
  • GET/api/v1/user/profile用户资料
  • GET/api/v1/user/dashboard仪表盘（积分 / 用量统计）
  • GET/api/v1/user/model-usage-stats按日期的模型用量统计
  • POST/api/v1/user/update-profile更新资料
配置 / 租户 useTenantConfigItems · configItemsLoader · TenantConfigContext
  • GET/api/v1/config/items拉取租户级配置项（authProxy 注入密钥/系统配置用）
  • GET/api/v1/tenant/config按 enterprise_code 拉租户配置
充值 / 计费 RechargeModal · OrderList
  • GET/api/v1/recharge/packages套餐列表
  • POST/api/v1/recharge/create创建充值订单
  • POST/api/v1/recharge/pay发起支付
  • GET/api/v1/recharge/query/{orderNo}查询订单状态
  • POST/api/v1/recharge/cancel/{orderNo}取消订单
  • GET/api/v1/recharge/list订单历史
团队管理（SaaS 租户 admin）MemberManagement
  • GET/api/v1/admin/members成员列表
  • POST/api/v1/admin/approve · /reject · /delete批准 / 拒绝 / 删除成员
数据面（推理）
  • PROXYmodel_service_url（sudorouter）个人模式 LLM 推理走登录返回的 sudorouter_key 代理，不打中控本身

企业模式

MOSS eeclaw.serverUrl（私有部署，需配置）
认证 eeclawBridge.ts
  • POST/api/v1/auth/tokentoken 交换/刷新（grant_type = api_key/password/oauth2/refresh）
  • POST/api/v1/auth/login企业登录（账号密码 / API Key）
  • GET/api/v1/auth/oauth2/config获取 OAuth2 登录配置
  • POST/api/v1/auth/logout注销
  • GET/api/v1/user/profile企业用户资料
  • GET/api/v1/tenant/config企业租户配置
远程 Agent 会话（MOSS 核心）MossSessionApi · MossWsConnection
  • POST/GET/api/v1/sessions创建会话（返回 ws_url/session_id/work_dir）/ 列出会话
  • GET/DEL/api/v1/sessions/{id}会话详情 / 删除
  • GET/api/v1/sessions/{id}/workspace/tree工作区文件树
  • GET/api/v1/sessions/{id}/workspace/file读工作区文件
  • GET/api/v1/sessions/{id}/skills/available会话可用技能
  • GET/PUT/api/v1/sessions/{id}/context会话上下文读写
  • POST/api/v1/sessions/{id}/terminate终止会话
  • POST/api/v1/sessions/{id}/resume恢复会话
  • WSws_url（建会话返回）实际对话流：user/assistant/tool_use/result…
模型 MossSessionApi
  • GET/api/v1/models/available可用模型列表
  • GET/PUT/api/v1/users/me/model（或 /users/{id}/model）用户默认模型查询 / 设置
远程定时任务 MossCronApi
  • CRUD/api/v1/cron/jobs（+ /{id}）远程定时任务增删改查（区别于个人模式的本地 cron）
密钥托管 moss-secret-client · EnterpriseSecretSection
  • GET/PUT/DEL/api/v1/me/secrets/{ns}/{key}用户密钥读 / 写 / 删
  • GET/api/v1/me/authorized-system-configs授权可用的系统配置
企业 MCP 管理 EnterpriseMcpSettings/api/
  • CRUD/api/v1/me/mcp-servers（+ /install-json、/{id}）用户 MCP 服务器管理
  • GET/api/v1/me/mcp-templatesMCP 模板
  • GET/api/v1/tenant/mcp-policy租户 MCP 策略
  • SSE/api/v1/mcp/eventsMCP 事件流
技能 / Agent 分发与同步 process/sync/
  • GET/api/v1/skills/installed（+ -detail）已装技能（远端 → 本地同步）
  • GET/POST/api/v1/skills/tenant（+ /publish）租户技能库 / 发布
  • POST/api/v1/skills/custom上传自定义技能
  • GET/api/v1/agents/installed（+ -detail）已装 Agent
  • GET/POST/api/v1/agents/tenant（+ /publish）租户 Agent 库 / 发布
  • POST/api/v1/agents/custom上传自定义 Agent
远程渠道 RemoteChannelProvider
  • CRUD/api/v1/channels/plugins（+ /{id}/enable…）远程 IM 渠道插件管理

两模式共用的其它远端（不属于上面两台服务器）

服务端点功能备注
Nexus（本地 daemon localhost:12022） /api/v2/secrets、/password_vault、/files/list、/catalog/*、/aspects、/ops/replay 本地密钥库（Vault）+ VFS 虚拟文件系统 + 知识图谱元数据 在本机，不出网（/api/v2 为 Nexus 专属）
QMS 遥测（sudowork-qms.sudoprivacy.com） /api/v1/telemetry/batch、/api/v1/crash/events/batch 性能遥测 / 崩溃上报 个人模式默认开 · 企业模式关 · 开关 telemetry.enabled
大模型推理 个人 = sudorouter(model_service_url)；企业 = MOSS / 本地直连 LLM 推理数据面 由 Agent CLI 子进程发起，非主进程
🧭 一句话总结：个人模式是数牍 SaaS 中控那一套（验证码登录、充值计费、用量、团队管理、配置下发）；企业模式是私有 MOSS 那一套（token 鉴权、远程会话执行、模型/定时/密钥/MCP/技能·Agent 分发、远程渠道）。企业模式比个人模式多出完整的远程 Agent 执行与租户治理能力。
