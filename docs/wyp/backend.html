2Moss Server（企业远程 Agent）WebSocket REST

会话类型 remote-agent 的后端。企业模式下不在本地 spawn CLI，而是连到远程 Moss 服务跑 Agent。

项实现
关键文件src/agent/remote/MossWsConnection.ts、src/process/remote/MossSessionApi.ts、src/process/bridge/mossBridge.ts、src/process/bridge/eeclawBridge.ts
端点来源企业配置 config.mossServerUrl / ProcessConfig 的 eeclaw.serverUrl，无硬编码默认，必须配置或环境变量
REST 端点令牌交换 POST {serverUrl}/api/v1/auth/token；建会话 POST /api/v1/sessions；列会话 GET /api/v1/sessions
WebSocket地址 ws_url 由建会话响应返回；消息为逐行 JSON（按 \n 切分后逐行 parse）
鉴权双层：① moss_sk_xxx API Key 或密码 → 交换 JWT access_token；② 之后 HTTP/WS 都带 Authorization: Bearer + X-Device-Id（设备身份）。过期前 5 分钟用 refresh_token 主动刷新

Session 创建 / 恢复

恢复模式
若 config.wsUrl || sessionId 已存在 → 复用，跳过建会话，直连已分配的 ws_url
创建模式
交换 token → POST /sessions 拿 {session_id, ws_url, work_dir, runtime} → 持久化 → 开 WS

收发事件：客户端发 user（用户消息）、control_request（权限响应 / 中断 / 切模型）；服务端发 hello / system / assistant / tool_use / tool_progress / result（含 cost、usage、耗时）/ control_request（权限请求）等。与本地 ACP 的消息语义对齐。

3Nexus（VFS + 密钥托管）gRPC HTTP

Nexus 是一个本地 daemon（nexusd-cluster 进程，绑定 127.0.0.1:12022），统一封装两件事：VFS 虚拟文件系统 和 密钥库（Vault）。它本身在本机，但应用通过它管理可能托管在远端的机密。

子能力协议用途
VFS 文件 I/OgRPC（native addon native/nexus-napi）Agent 工作区沙箱：read/write/readdir/mkdir/stat。daemon 由 DynamicNexusVfsService 启动（--data-dir ~/.nexus-vfs）
密钥库 VaultgRPC 二进制 password-vault.secret_*（Protobuf）托管所有机密：IM 凭证、各家大模型 API Key、ACP OAuth refresh_token、JWT 密钥
知识图谱元数据HTTP REST /api/v2/aspects 等catalog/schema 查询（fetch-client.ts）
事件流SSE /sse（支持 Last-Event-ID 断点）基础设施已备
项实现
关键文件src/common/nexus/{nexus-vfs-client,fetch-client,sse-client,config,nexus-secret-client,secret-cache,secret-migration}.ts、src/process/services/nexus-vfs/DynamicNexusVfsService.ts、src/process/bridge/nexusBridge.ts
端点配置优先级构造参数 > 配置文件(nexus.yaml / ~/.nexus/config.yaml) > 环境变量(NEXUS_URL) > 默认 http://localhost:12022
鉴权HTTP: Authorization: Bearer {apiKey} + X-Agent-ID / X-Nexus-Subject / X-Nexus-Zone-ID；gRPC 调用传 authToken
🔐 密钥迁移：首次会把本地 SQLite 里的机密迁移进 Nexus Vault（命名空间如 channels:telegram:token、ai_platforms:anthropic:xxx、acp:access_token），迁移后从本地删除并打 secret_migration_version 标记。启动时 secret-cache.preload() 把全部密钥预载进内存 Map，运行时同步读取。

4大模型 Provider（AI 推理）

如总览所述，CLI 子进程直连 LLM API，应用侧的 authProxy（src/process/services/authProxy/AuthProxyServer.ts）只做密钥注入，且仅监听 127.0.0.1、带 token 认证与 SSRF 防护。

6MCP 服务器 stdio SSE/HTTP

支持 3 种连接：本地 stdio（spawn 子进程，如 npx -y xxx）、远程 SSE、远程 HTTP / streamable_http。只有后两种算"出网"。

项实现
关键文件src/process/services/mcpServices/{McpProtocol,McpService}.ts、src/process/bridge/mcpBridge.ts
远程配置{ type: 'sse' | 'http', url, headers }（headers 可带 Bearer）
配置存储config.txt 的 mcp.config（IMcpServer[]），不在 SQLite
同步McpService.syncMcpToAgents() 把配置并发下发到各 Agent（Claude / Qwen / Gemini ...）；testMcpConnection() 测连通
mcporter格式转换器：Sudowork MCP 配置 ↔ mcporter 配置（src/process/services/mcporter/mcporterConfig.ts），用于和 Claude Code 等第三方工具互通
⚠️ 纠偏：有探索结论误称"MCP 配置存 SQLite via upsertChannelPlugin"——那是 IM 渠道插件的存储，与 MCP 无关。MCP 配置实际在 config.txt 的 mcp.config（见 数据库文档的存储边界）。

类型端点内容
