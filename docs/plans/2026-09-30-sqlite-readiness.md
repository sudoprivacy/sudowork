# SQLite 数据接入验证记录

验证日期：2026-09-30。

## 结论

已完成 SQLite 接入、字段读取、数据预览、结构同步、对象映射、普通关系查询、SQL 汇总与发布版本执行的业务链路验证。测试使用本机 Electron 的真实 `better-sqlite3` 原生驱动和真实本体工作台存储。

当前验证环境为 Electron 40.8.5、Node 24.14.0、SQLite 3.51.2。样例数据库包含 150 个客户、240 个订单、240 条订单明细、商品、汇总视图、空表、大整数与二进制字段，以及带引号的表名。汇总结果为 600000 分。

## 本次修复与补齐

- “添加文件”和“导入本体”说明统一为悬浮提示，也支持键盘聚焦查看。
- SQLite 连接支持文件选择；通过“添加文件”选择 `.db`、`.sqlite`、`.sqlite3`、`.db3` 时会建立数据库连接。
- 数据连接保留在页面中，空数据库也可重新扫描；新增数据表可被发现。
- 重扫复用原有表标识及未变化字段的业务含义。移除的表标记为来源已移除，恢复后同步可清除该状态。
- 同一个文件的不同连接使用独立的数据来源标识。
- 使用 `table_xinfo` 读取生成列，保留主键顺序、空值约束、默认值及外键目标；排除虚拟表的内部存储表和隐藏内部列。
- 修正带引号表名的读取，保留中文、空格和 `#` 文件路径。
- 超出 JavaScript 安全整数范围的 INTEGER 以字符串传递，避免标识精度损失；BLOB 以 Base64 传递，NULL 保持为空值。
- SQLite 对象查询在数据库中先筛选再限制返回条数，可以查到第 100 条以后的记录。
- 同库普通直接关系与中间表关系使用 SQL JOIN，正反向查询和匹配总数基于数据库实际数据。
- SQL Function 支持 SQLite 的只读 WITH/CTE 查询；SQLite 自身解析单条语句，字符串中的分号不会被误判为多条 SQL。
- 写入仅在明确授权为可写的连接和 Action 中执行，并启用 SQLite 外键约束。

## 原生集成验证

共 12 项原生 SQLite 场景通过：

1. 表、视图、生成列、复合主键、外键、默认值及带引号名称。
2. 空表、视图、64 位整数、BLOB 和 NULL 预览。
3. 超出预览窗口的对象查询及超大整数标识查询。
4. 双向直接关系查询，以及超过前 100 条数据的基数违规检查。
5. 中间表多对多查询、总匹配数及结果截断标记。
6. 全库 CTE 汇总、发布、Working 修改后的固定版本查询、智能体版本绑定及源文件不变检查。
7. 不存在或无效数据库文件的失败处理。
8. 新增表扫描、原有标识和业务含义保留、移除及恢复来源。
9. 两个连接使用同一文件时的数据来源标识隔离。
10. WAL 模式已提交数据读取与 FTS 内部存储表过滤。
11. 普通复合主键、INTEGER PRIMARY KEY DESC、WITHOUT ROWID 及虚拟生成列的元数据。
12. 只读拒绝写入、显式授权后的 Action 写入、外键错误及多语句拒绝。

此外，100 项相关单元和组件回归测试通过，桌面及 Renderer TypeScript 检查通过。

## 复现

在 `apps/desktop` 目录执行：

```sh
bunx vitest run tests/unit/ontologySqlite.native.test.ts
```

入口会自动启动与原生模块 ABI 匹配的 Electron 子进程。未安装 Electron 的环境会明确跳过原生测试。本次本机已实际执行全部 12 项原生场景。

## 使用范围

- 预览最多读取 100 条；对象查询及普通关系查询先在数据库中完成筛选，再限制返回数量。SQL 汇总按原始数据库计算。
- 当前连接界面以只读方式接入。写入测试在临时库中显式启用了可写连接和 Action。
- 原生测试中的 SQLite 数据源与本体存储均为真实文件；智能体安装、MCP 注册采用测试替身，未依赖真实模型生成结果。
- 上述关系全量查询适用于同一 SQLite 数据库内的普通直接关系和中间表关系。跨数据库及递归、对称、无环关系沿用现有通用执行路径，不应将本次验证视为所有高级关系语义的全量验证。
