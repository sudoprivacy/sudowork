本轮新增：平台感表达

在不把产品做成“大而全平台”的前提下，前端明确展示三件事：知识资产来源、来源系统输入、以及后续扩展路径。

结构化资产 来源系统 扩展路径
历史模板库
不只是一份模板，而是按采购类型、行业、客户侧风格沉淀的结构化模板资产。
条款库
将资格条款、商务条款、合同条款沉淀为可解释、可复用的结构化条款资产。
行业知识库

后续扩展路径

当前先做编制工作台，但前端要把后续可扩路径讲清楚，避免客户把它理解成单点工具。

Phase 1：先做编制项目创建、材料解析、字段确认、模板推荐、整稿生成、审查与导出。
Phase 2：投标解析后续扩到投标文件解析、应标点识别、资质材料理解。
Phase 3：评标辅助在后续阶段承接评审规则、评分要点、辅助评标与报告输出。
Phase 4：风险识别进一步扩到围串标检测、异常条款识别与全流程风险监控。

后续扩展路径（方案表达）

建议在 PRD / 汇报 / 原型中明确告诉客户：当前先做编制，但不是止步于编制。

一期：招标文件编制项目创建、材料解析、字段确认、模板推荐、整稿生成、审查导出。
二期：投标文件解析接应标点识别、资质/业绩材料理解与投标文件结构化。
三期：评标辅助接评审规则、评分要点、辅助评标和报告输出。
四期：风险识别扩展到围串标检测、异常条款识别与全流程风险监测。
