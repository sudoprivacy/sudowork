## 1. 背景

当前项目已经完成 Renderer UI Token 硬切，并更新了：

```text
src/renderer/styles/variables.css
uno.config.ts
```

新的 `variables.css` 是设计 Token 的唯一来源，`uno.config.ts` 提供与这些 Token 对齐的语义 utility 和通用 shortcut。后续 UI 对齐不能重新引入截图色值、旧 Token 或另一套局部样式体系。

本次目标是让 Electron 应用壳层向目标站点靠近，重点包括：

- 左侧面板与右侧内容区的表面层级；
- 侧栏宽度、内边距和纵向密度；
- 顶部品牌区域；
- 新建会话入口；
- 会话历史行的默认、悬浮和选中状态；
- 左下角个人信息、账户弹层和设置页返回入口；
- 标题栏与 Electron 原生窗口区域的衔接。

目标截图与当前截图的关键表面差异是：

| 区域 | 目标 | 当前主要问题 |
|---|---|---|
| 左侧面板 | 浅灰次级表面 | 基本接近目标色，但布局和控件卡片感偏重 |
| 右侧内容 | 白色基础表面 | 与左侧同为浅灰，缺少双表面层级 |
| 分隔 | 由左右表面色差自然形成 | 不再额外绘制分隔线 |
| 新建会话 | 左对齐、弱背景导航行 | 当前为居中、有常驻边框的大按钮 |
| 左下角设置 | 位于个人信息弹层 | 设置页替换为返回主界面 |

当前右侧背景问题并不是 Token 值错误，而是旧 class 静默失效：

```tsx
<ArcoLayout.Content className='bg-2 layout-content ...'>
```

`bg-2` 已被 `uno.config.ts` 的 blocklist 禁止生成，内容区因此保持透明并透出 `.layout` 的 `--secondary` 背景。根因修复应是为内容区使用现有的 `bg-background`，而不是新增颜色或局部覆盖。

## 2. 已确认决策

1. 第一阶段只调整应用壳层，不改聊天正文、输入框和右侧 Workspace。
2. 普通页面的设置入口放在个人信息弹层中；设置页面左下角整体替换为返回主界面。
3. 尺寸按目标站点的视觉比例和信息密度适配 Electron，不照抄截图物理像素。
4. 侧栏顶部只保留应用名称，不显示 Logo。
5. 优先复用最新的 `variables.css` Token、`uno.config.ts` utility 和适用的 shortcut。
6. 默认不修改 Token 值；先修复语义选择、旧 class 失效和布局问题。
7. 不引入新依赖，不新增独立主题层，不恢复旧 Token 兼容接口。
8. 仅在多个壳层入口形成稳定、完全相同的样式组合后，才考虑新增 shortcut；第一版不提前抽象。
9. 保留 Electron 窗口拖拽区、macOS 红绿灯安全区、侧栏收起和白标配置能力。

## 3. 目标与非目标

### 3.1 目标

- 建立清晰的左灰右白双表面应用壳层。
- 让标题栏、侧栏和右侧内容区形成连续一致的背景关系。
- 调整侧栏比例、内边距和列表密度，使其接近目标站点。
- 将新建会话从卡片按钮收敛为侧栏导航入口。
- 将设置从账户下拉菜单提升为常驻入口。
- 保留登录、退出、新建会话、设置往返等现有行为。
- 清理本次涉及区域中的旧 UnoCSS class 和业务层 Arco Token 直引。
- 验证亮色、暗色、侧栏收起和 Electron 窗口交互。

### 3.2 非目标

本阶段不负责：

- 复刻目标站点中本项目不存在的业务导航项；
- 调整 `/guid` 页面主体、聊天消息、发送框或 Prompt 卡片；
- 调整 Conversation 的右侧 Workspace、Preview 或 Task Panel；
- 全仓迁移旧 UnoCSS class；
- 重写 `variables.css` 的颜色体系；
- 为一次性样式新增通用组件、主题配置或设计系统抽象；
- 逐像素复制浏览器截图中的浏览器顶栏结构。

## 4. Token、utility 与 shortcut 使用原则

### 4.1 优先级

每个视觉需求按以下顺序实现：

1. 判断元素的真实语义；
2. 从 `variables.css` 选择已有 Token；
3. 优先使用 `uno.config.ts` 已暴露的语义 utility；
4. 已有 shortcut 完全匹配时直接复用；
5. 结构性、Electron 特有或依赖动态宽度的样式放在 `base.css`；
6. 只有现有能力无法表达且需求稳定时，才讨论新增 Token、rule 或 shortcut。

### 4.2 本区域建议映射

| 壳层语义 | Token | UnoCSS 写法 |
|---|---|---|
| 右侧基础表面 | `--background` | `bg-background` |
| 左侧次级表面 | `--secondary` | `bg-secondary` |
| 默认悬浮 | `--accent` | `hover:bg-accent` |
| 按下状态 | `--fill-deep` | `active:bg-fill-deep` |
| 弱控件填充 | `--fill-shallow` | `bg-fill-shallow` |
| 主要文字和图标 | `--foreground` | `text-foreground` |
| 次要文字和图标 | `--foreground-secondary` | `text-foreground-secondary` |
| 提示文字 | `--foreground-tertiary` | `text-foreground-tertiary` |
| 默认业务边框 | `--border` | `border-border` |
| 强边界 | `--border-deep` | `border-deep` |

### 4.3 可以直接复用的现有 shortcut

```text
f-center
scrollbar-hide
rounded-md
rounded-lg
```

`card` shortcut 不适合侧栏导航行，因为它附带 padding、阴影、hover 位移等卡片行为。本次不能为了复用 shortcut 而制造错误语义。

### 4.4 继续放在 `base.css` 的结构样式

以下样式与动态宽度、浏览器窗口结构或伪元素有关，不强行改写为长串原子类：

- 标题栏左、右表面分色；
- `-webkit-app-region: drag/no-drag`；
- 侧栏展开和收起动画；
- 依赖 `--layout-sider-width` 的定位；
- 会话行尾部随状态变化的渐隐遮罩。

## 5. 目标壳层结构

```text
┌─────────────────────────────────────────────────────────┐
│  macOS 红绿灯 / 标题栏拖拽区                            │
│  ┌──────────────────┬──────────────────────────────────┐ │
│  │ secondary        │ background                       │ │
├──┼──────────────────┼──────────────────────────────────┤─┤
│  │ App Name         │                                  │
│  │                  │                                  │
│  │ + 新建会话       │            Outlet                │
│  │                  │                                  │
│  │ 会话历史         │                                  │
│  │                  │                                  │
│  │                  │                                  │
│  │ 个人信息菜单     │                                  │
│  │ （设置页：返回） │                                  │
│  └──────────────────┴──────────────────────────────────┘ │
└─────────────────────────────────────────────────────────┘
```

设计特征：

- 左侧使用 `--secondary`，右侧使用 `--background`；
- 左右区域仅通过表面色差区分，不增加分隔线或阴影；
- 品牌区、新建会话、历史列表和底部入口共享同一左侧对齐基线；
- 新建会话、设置和账户入口默认不呈现独立卡片边框；
- hover 才显示 `--accent`；
- 圆角和行高保持克制、统一。

## 6. 实施阶段

### Phase 1：修复双表面壳层

**涉及文件：**

```text
src/renderer/layouts/layout.tsx
src/renderer/styles/base.css
```

**实施内容：**

1. 将右侧 `.layout-content` 的失效 `bg-2` 改为 `bg-background`。
2. 左侧 `.layout-sider` 继续使用 `--secondary`。
3. `.layout` 只作为缝隙和动画期间的壳层兜底背景，不再决定右侧内容颜色。
4. 标题栏展开时按 `--layout-sider-width` 分为左侧 `--secondary` 和右侧 `--background`。
5. 侧栏收起时标题栏恢复为完整的 `--background`，避免残留灰色左段。
6. 删除 `app-shell--sider-divider::after`，由左右表面色差自然形成边界。
7. 侧栏宽度保持为 `260px`，由单一 `--layout-sider-width` 驱动，不分散硬编码。
8. 验证 TitleBar 的侧栏开关、Workspace 开关、Windows 控制按钮和 macOS 红绿灯区域不受影响。

**完成标准：**

- 亮色模式左侧为次级灰色，右侧为基础白色；
- 暗色模式左右表面仍有可辨识层级；
- 侧栏展开和收起过程中没有透明穿透、背景闪烁或残留分色；
- 左右表面边界连续，不出现额外分隔线或缝隙；
- 窗口拖拽和控制按钮正常。

### Phase 2：调整品牌区和侧栏几何

**涉及文件：**

```text
src/renderer/layouts/layout.tsx
src/renderer/layouts/components/Sider.tsx
```

**实施内容：**

1. 侧栏顶部不显示 Logo，只保留 `TenantConfig` 提供的应用名称。
2. 降低当前应用名 `20px / 800` 的视觉重量，使用已有字号和 foreground Token。
3. 统一品牌区、侧栏主体和底部入口的水平 padding。
4. 调整品牌区高度以及与新建会话之间的距离，使顶部结构更紧凑。
5. 保留点击应用名称回到新会话和触发调试入口的现有行为。
6. 不把品牌行抽成新组件，不新增只服务本页面的 shortcut。

**完成标准：**

- 应用名称清晰可见，但不压过侧栏功能入口；
- 所有侧栏内容拥有稳定的左对齐基线；
- 白标应用名称替换后仍能正确截断。

### Phase 3：重做新建会话入口

**涉及文件：**

```text
src/renderer/layouts/components/Sider.tsx
```

**实施内容：**

1. 从当前居中、有常驻边框的大按钮改为左对齐导航行。
2. 默认使用透明背景，不显示常驻边框和阴影。
3. hover 使用 `hover:bg-accent`，active 使用 `active:bg-fill-deep`。
4. Plus 图标和文案使用规范 foreground Token。
5. 行高、圆角和水平 padding 与会话历史行、设置入口保持统一。
6. 保留现有逻辑：
   - 清理侧栏 Tooltip；
   - 清除 `guid.lastSelectedAgent`；
   - 触发 `guid.reset`；
   - 导航到 `/guid`。
7. 增加或保留明确的可访问名称和键盘可操作能力；实现时优先使用 Arco `Button`，若其默认结构无法满足整行导航样式，再使用语义明确的原生 `button`，不继续使用只有 `onClick` 的普通 `div`。

**完成标准：**

- 新建会话在视觉上属于导航系统，而不是独立卡片；
- 鼠标、键盘和屏幕阅读器均可触发；
- 原有重置行为没有变化。

### Phase 4：统一会话历史行

**涉及文件：**

```text
src/renderer/pages/conversation/grouped-history/ConversationRow.tsx
src/renderer/pages/conversation/grouped-history/index.tsx
src/renderer/styles/base.css
```

**实施内容：**

1. 会话行与新建会话入口采用一致的行高、圆角和水平节奏。
2. 默认文字使用 `text-foreground-secondary`，hover/selected 提升到 `text-foreground`。
3. 默认不显示边框或阴影。
4. hover 使用 `--accent`。
5. selected 使用现有规范 Token 组合形成明确但克制的选中状态，不引用 Arco `--primary-6`。
6. 让 `--row-fade` 在默认、hover 和 selected 状态下跟随实际背景。
7. 分组标题降低强调度，迁移 `text-secondary` 等旧 class。
8. 只迁移本次壳层可见路径，不顺带重构导出 Modal、批量操作或整个 grouped-history 模块。

**完成标准：**

- 历史列表不再呈现多个独立卡片；
- 默认、hover、selected 三种状态可辨识；
- 文本截断、Pin、更多菜单、Cron 状态和终端状态不回归；
- 列表尾部渐隐不露出错误底色。

### Phase 5：个人信息弹层和设置页返回

**涉及文件：**

```text
src/renderer/layouts/components/Sider.tsx
src/renderer/layouts/components/SiderFooter.tsx
```

**默认路由结构：**

1. 左下角只显示个人信息区域。
2. 点击个人信息打开弹层，弹层包含设置以及登录或退出。
3. 点击设置时：
   - 访客进入 `/settings/model`；
   - 已登录用户进入 `/settings/profile`。

**设置路由结构：**

1. 主体继续显示现有 `SettingsSider`。
2. 左下角个人信息整体替换为“返回主界面”。
3. 点击后回到进入设置前的非设置页面。
4. 不新增全局路由状态；继续复用现有 `lastNonSettingsPathRef`。

**视觉状态：**

- 默认透明；
- hover 使用 `--fill-default`；
- active 使用 `--fill-deep`；
- 不显示常驻卡片边框；
- 普通态个人信息和设置态返回入口占用同一底部区域。

**完成标准：**

- 设置只出现在个人信息弹层中；
- 设置页左下角只显示返回主界面；
- 设置页能返回进入前页面；
- 登录、退出和访客入口没有功能损失。

### Phase 6：清理本区域旧样式接口

只清理本计划涉及文件，不进行全仓机械替换。

| 旧接口 | 候选新接口 | 选择依据 |
|---|---|---|
| `bg-2` | `bg-background` | 右侧是页面基础表面 |
| `bg-subtle` | `bg-muted` / `bg-fill-shallow` | 区分弱区域和控件填充 |
| `hover:bg-hover` | `hover:bg-accent` | 交互悬浮状态 |
| `active:bg-fill-2` | `active:bg-fill-deep` | 按下覆盖层 |
| `text-secondary` | `text-foreground-secondary` | 次要文字和图标 |
| `bg-fill-3` | `bg-fill-deep` | 强填充状态 |
| `!bg-active` | 规范 Token utility | 根据 selected 的真实语义选择 |
| `text-1` / `text-2` | `text-foreground*` | 明确文字层级 |
| `rgba(var(--primary-6), ...)` | 规范 Token 或 `color-mix` | 业务代码不直接依赖 Arco Primary |

完成后对目标文件运行扫描，确认没有继续使用上述旧接口。

## 8. 实施顺序与视觉检查点

为了避免在错误底色和错误比例上反复调控件，按以下顺序推进：

1. 完成 Phase 1：双表面、标题栏分色、侧栏宽度；
2. 使用与当前截图一致的 Electron 窗口尺寸重新截图；
3. 确认左右比例和背景层级后，完成 Phase 2–3；
4. 再次截图确认品牌区和新建会话；
5. 完成 Phase 4–5，统一历史行和底部入口；
6. 完成旧 class 扫描、暗色检查和自动验证。

每个检查点优先比较：

- 左右表面边界；
- 侧栏宽度占比；
- 品牌区与首个入口的间距；
- 新建会话、历史行、设置入口的统一行高；
- 底部入口是否稳定贴底；
- 文本和图标的强调层级。

## 11. 风险与约束

### 11.1 旧 class 静默失效

TypeScript 和 JSX 不会报告 UnoCSS class 未生成。所有修改文件必须做旧接口扫描，并在运行中的 `/@id/virtual:uno.css` 或最终视觉中确认规范 utility 已生成。

### 11.2 标题栏属于 Electron 结构

目标截图来自浏览器，不能直接复制其顶栏。实现必须保留：

- Electron 拖拽区域；
- macOS 红绿灯空间；
- Windows/Linux 窗口控制按钮；
- 可交互区域的 `no-drag`。

### 11.3 侧栏宽度影响内容可用空间

侧栏宽度保持项目既有的 `260px`，不根据截图比例引入新的响应式宽度系统。

### 11.4 左下角模式切换不能混杂

普通页只显示个人信息入口，设置位于其弹层内；设置页必须将该区域整体替换为返回主界面，不能同时显示账户信息。账户弹层仍需保留登录和退出。

### 11.5 不提前抽象 shortcut

新建会话、历史行、设置和账户入口虽然视觉相近，但结构和行为不同。第一版优先用现有 utility 表达；只有实现后确认存在稳定、完全相同的重复 class 组合，才考虑一个小型 `sidebar-action` shortcut。

## 12. 完成定义

1. 左灰右白双表面壳层与目标视觉方向一致；

3. 新建会话改为导航行样式，且原行为不变；
4. 会话历史行的密度和交互状态完成局部迁移；

6. 本区域不再使用已 blocklist 的旧 UI class；
7. 默认没有修改 `variables.css` 和 `uno.config.ts`；
8. 亮色、暗色、侧栏收起和设置往返完成视觉验证；
9. 单文件 ESLint、TypeScript、相关测试和全量测试完成；
