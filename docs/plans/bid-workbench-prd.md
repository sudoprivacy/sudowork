# 招标文件编制工作台 PRD

## 1. 文档信息

- 产品名称：招标文件编制工作台
- 所属产品：Sudowork WebUI / Desktop
- 当前阶段：从 P2 MVP 升级到可对客演示的真实能力版
- 文档目标：定义可直接给客户演示的完整产品能力、用户流程、AI 能力、人工交互节点和验收标准

## 2. 背景与问题

当前 `bid-projects` 已有一版可运行的工作台 MVP，支持：
- 登录后进入招标编制入口
- 新建项目
- 查看分析页
- 进入编辑页
- 查看 AI 侧边栏建议
- 查看底部合规问题
- 保存并导出 DOCX

但当前版本仍存在明显短板：
- 用户仍需从空白 Markdown 或接近空白模板开始写
- 上传材料只停留在文件名层，无法形成真正的资料池
- AI 没有自动生成整份招标文件初稿
- 合规与依据能力仍偏演示态
- 无法清晰证明内容来自材料与知识库，而不是“凭空生成”

因此，本次升级目标不是继续美化页面，而是把产品从“AI 辅助编辑器”升级为“AI 自动生成 + 人工确认 + 审查修复 + 导出”的完整工作台。

## 3. 目标

### 3.1 产品目标

让用户在 Sudowork 中完成完整闭环：
1. 新建项目
2. 上传招标相关材料
3. 自动解析材料并抽取关键事实
4. 人工确认冲突或缺失信息
5. AI 自动生成完整招标文件初稿
6. 章节级修订 / 联动修订 / 模板切换
7. 合规审查与一键修复
8. 导出 DOCX

### 3.2 演示目标

客户演示时，必须让对方看到这 4 个核心价值：
- 会自动生成整份初稿
- 明确基于上传材料和知识增强生成
- 会识别风险并给出修复建议
- 可以导出成可继续使用的 Word 文件

### 3.3 非目标

本阶段不追求：
- 多人实时协作
- 审批流
- 外部第三方采购平台对接
- 全格式 OCR 一次性覆盖
- 富文本编辑器重构

## 4. 目标用户

### 4.1 直接用户
- 招采专员
- 采购实施人员
- 项目经理
- 售前/解决方案人员
- 客户单位的采购办、信息中心等业务人员

### 4.2 间接用户
- 法务/合规审核人员
- 部门负责人
- 客户演示中的决策层与信息化负责人

## 5. 核心场景

### 场景 A：从零生成招标文件初稿
用户填写项目基础信息并上传材料，系统自动生成一整份结构化招标文件初稿。

### 场景 B：材料不完整但想快速出稿
用户只有部分材料，系统先基于表单和已有材料生成基础稿，并标记待补充项。

### 场景 C：对已有初稿做章节级优化
用户对某一章节不满意，希望 AI 重生成当前章节或给出多个备选条款。

### 场景 D：审查与修复
用户希望系统自动指出招标文件中的风险、缺失、冲突，并一键修复后再次审查。

### 场景 E：面向客户演示
演示者使用标准 demo 项目材料包，在浏览器内完整走通“上传 → 生成 → 审查 → 修复 → 导出”的流程。

## 6. 完整业务流程

### 6.1 主流程
1. 登录 WebUI
2. 从左侧进入“招标编制”
3. 点击“新建项目”
4. 填写项目基础信息
5. 上传项目材料
6. 系统解析材料并抽取候选事实
7. 用户确认冲突字段/缺失字段
8. 系统推荐模板并规划章节
9. 系统接入企业知识增强与项目材料上下文
10. AI 分章节生成完整初稿
11. 用户进入编辑页查看整稿
12. 用户按章节修订 / 重生成 / 联动修订
13. 系统运行合规审查
14. 用户应用修复建议
15. 再次审查
16. 保存版本
17. 导出 DOCX

### 6.2 异常分支
- 材料上传失败：允许重试
- 材料解析失败：提示原因并允许跳过或更换文件
- 字段冲突：要求人工确认
- 生成失败：保留已完成步骤并支持重试生成
- 审查失败：不阻塞导出，但标记“审查未完成”

## 8. AI 能力设计

### 8.1 AI 自动处理能力
- 材料摘要
- 候选事实抽取
- 冲突检测
- 模板推荐
- 章节规划
- 完整初稿生成
- 单章节重生成
- 联动修订建议
- 审查问题发现
- 修复建议生成

### 8.2 知识增强能力
复用现有 Dify enhancement 与企业知识增强机制，接入既有 RAGFlow / 企业知识库：
- 法规制度知识库
- 通用模板/行业模板知识库
- 客户私有模板与条款知识库
- 当前项目材料形成的上下文知识

### 8.3 引用依据能力
每次生成或审查尽量带回：
- 来源文件
- 来源片段
- 法规/模板依据
- citations

## 9. 人工交互节点设计

### 必须人工确认的节点
- 冲突字段最终值

- 模板切换是否覆盖已有内容
- 高影响章节批量更新
- 审查建议是否应用
- 最终导出前确认

### 必须提供的人工操作
- 确认字段
- 修改字段
- 拒绝候选值
- 锁定章节
- 手动编辑正文
- 重生成当前章节
- 应用修复建议
- 忽略审查问题
- 查看依据

- 冲突候选

### 处理策略
- 先做文本文档材料
- 后续补预算表、扫描件、批量压缩包

## 14. 验收标准

### 可直接对客演示的条件
1. 黄金路径跑通
2. 自动生成整份初稿可见
3. 材料与知识增强依据可见
4. 合规审查与修复可见
5. DOCX 导出成功并可打开
6. 关键异常有兜底
7. 有标准演示材料包

### 如果未满足
若只完成部分阶段，则仅可内部验收，不建议直接对客户正式演示。
