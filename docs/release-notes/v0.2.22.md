# Sudowork v0.2.22 Release Note

> 自 v0.2.21 起包含 30 个功能与修复提交：24 个 fix、2 个 feat、4 个 test。此次发布重点是桌面端短信登录相关闪退的紧急修复。

## 重要修复

- 修复 macOS / Linux 在核心服务部分初始化失败后，点击“获取验证码”重新启动服务时可能直接退出的问题。端口清理现在只选择 TCP 监听进程，并排除当前进程，避免将 Electron 的客户端连接一起终止。Nexus 停止及网关清理使用同样的保护。
- 补充真实监听进程和客户端的集成回归，验证清理后客户端仍能响应；修复前两条清理路径均失败。
- macOS 桌面实例完成真实短信接收及登录验收。
- 修复启动更新调用 renderer ConfigStorage 获取服务地址时可能永久等待的问题，改用已有主进程配置初始化流程和同步地址解析。
- 修复 Sudocode 已安装版本识别，保留用户已有的更新版本。
- 改善 Windows 资源目录重试及恢复；统一原生工作区中技能名称和安装状态。
- 改善 WebUI 浏览器重连、路由加载重试、冷启动工作区等待和定时任务视图刷新。

## 重点新功能

- 增加私有 Agent 会话备份与恢复技能，并限制交互式下载时长，保留可读的 Sudocode 上下文。
- 增加可选的 sudohand 浏览器后端，完善原生浏览器操作兼容性。

## 工程重构与验证

- 同步 Nexus ABI 7 运行时与签名插件，增加旧版密钥库升级数据保留验证。
- 验证真实 Sudocode 经 gRPC 通道连接，补充 Moss Agent 会话隔离测试。
- 稳定 Windows 原生测试工具链、Electron SQLite 测试依赖及发布恢复流程。
- 新增真实端口清理、启动配置和发布元数据回归；TypeScript、修改文件 ESLint / Prettier 和桌面生产构建通过。最终组合通过完整 PR CI 后发布。

## 发布与自动更新

- 通过正式版本 tag 构建 Windows x64、macOS Intel / Apple Silicon 及 WebUI 发布包。
- GitHub 和 COS 均发布安装包、ZIP、blockmap 及对应架构更新元数据，COS 元数据在安装包验证完成后最后更新。
- 修复 0.2.21 发布流程曾遇到的 macOS 主更新文件为 DMG 导致 COS 校验失败的问题：发布前将主文件规范为对应架构的 ZIP，保留并校验各文件 SHA-512；同时覆盖 DMG 优先及 ZIP 优先的构建结果。
- COS 就绪后启用公共服务的版本更新开关，验证安装包与更新下载链路。
- 官方 0.2.21 的启动更新配置读取存在挂起问题；新版本无法修复旧进程自身的检查逻辑。未出现提示的旧版用户需要手动检查更新或下载安装包，不能承诺全部旧版自动升级。
