# SudoWork v0.2.23

## New Mac startup recovery

The pinned macOS FUSE plugin links `/usr/local/lib/libfuse3.4.dylib`. A new Mac without FUSE-T could install the plugin but fail to start Nexus because the dynamic loader could not resolve that library. Reinstalling the app retained the failing runtime. Previous cold-start CI installed FUSE-T before testing, hiding this condition.

The desktop installer now defers the optional FUSE plugin when its library is unavailable, removes stale managed FUSE files before starting Nexus, and retains the vault and local connector. Explicit mount setup checks daemon health before reporting the missing driver, then installs the deferred plugin after the user installs FUSE-T.

## Runtime repair

The startup screen's Nexus reinstall action now removes the current managed binary and plugin files after stopping Nexus. It preserves databases, node identity, custom files and standalone tools instead of deleting the legacy shared binary directory.

## Acceptance

- Reproduced the failure with the official COS v0.2.22 Intel installer and an isolated profile; denying access to FUSE dylibs reproduces Nexus startup failure and an ineffective reinstall button.
- Confirmed the published Apple Silicon plugin has the same external library dependency.
- Added real daemon acceptance before FUSE-T installation on macOS CI: startup, vault write, runtime repair and persisted vault read.
- Added filesystem and status regressions for deferred plugins, repair preservation, daemon stop failure and explicit mount setup.
