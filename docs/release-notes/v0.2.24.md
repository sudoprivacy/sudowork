# SudoWork v0.2.24

Online phone login, invitation registration, password, API key, and desktop OAuth2 callbacks now use one authentication flow in `@sudowork/common/authLogin`. Web cookie sessions and desktop IPC are adapters in `@sudowork/host-bridge/authLogin`; desktop model setup is isolated in `desktopLoginSetup`.

The shared flow validates authenticated identities, bounds an entire attempt to 45 seconds, and commits renderer authentication only after required setup succeeds. Its abort signal bounds web requests; IPC results that arrive after the deadline cannot trigger subsequent renderer writes or authentication. Server selection and mode preparation have their own 10-second bound. Failures log the stage and error category without credentials.

Main-process authentication storage remains owned by the desktop bridge. The renderer no longer rewrites those tokens during finalization. Auxiliary reporting initialization runs independently of login completion. Existing model selection, custom provider restoration, and managed execution policy remain covered by regression tests.

The login page shares submission/loading/error handling across its standard forms. It restores the button on errors, prevents duplicate submits, and exposes localized timeout and local-setup failures. Web login requires a valid cookie session instead of accepting an empty identity.

Validation covers both transports and their request shapes, all supported grants, server rejection, missing web sessions, stalled HTTP/IPC, late responses, desktop model persistence failures, and button recovery/retry. The customer's precise environmental trigger for the reported spinner has not yet been captured; the unbounded-wait failure mode is tested with deliberate IPC failure injection.
