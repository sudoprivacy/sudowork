# SudoWork 0.2.38

## Browser sessions

- Connect an already-running Chrome profile through **Connect my Chrome** in
  Desktop's BrowserPanel. The panel and independent viewer operate the same
  browser, cookies and tab. Explicit disconnection leaves Chrome running.
- Taking control cancels pending native agent questions and pauses agent tools
  before acknowledging the handoff. Cancelled questions stay cancelled after
  reloading the conversation. Returning control starts with a fresh observation.
- Recover a stopped personal attachment after a worker crash and explicitly
  disconnect it. Profile selection remains an explicit user action.
- Keep the handoff note beside **Return to AI**, and fit BrowserPanel's padding
  inside its height so the final input remains visible.
- Reduce redundant frame, attachment and state requests in the shared remote
  viewer used by Desktop and WebUI.
- Pin the browser runtime and bundled skill to public ai-dev-browser 0.58.0.

## Validation

Real Chrome journeys cover headless and headful profiles, both extension
WebSocket backends, trusted Unicode input, one submission, worker crashes and
safe disconnection. A real Electron and Sonnet 4.6 journey covers native agent
questions, persisted cancellation, the independent viewer and exact model
readback after the user returns control.
Fresh Electron environments also exercise the product's first-use installer
against public PyPI. A public WebUI journey against production Moss 0.1.73
verifies trusted input and durable termination during concurrent metadata reads.
The cloud fixture also covers sign-in persistence across a browser restart and
exact AI readback through browser tools after Return.

The full deployment and device acceptance matrix is tracked in
[Browser sessions](../sudowork-browser-sessions.md).
