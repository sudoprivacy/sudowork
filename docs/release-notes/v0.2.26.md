# v0.2.26

Upgraded desktop installations that retained the retired public login address could receive SMS codes but reject the old server's successful response. Startup now migrates that exact public default to hosted Moss and resets both process and renderer sessions once, before old credentials can be restored. Private URLs, managed deployments, conversations, and preferences are preserved. The affected customer confirmed that selecting the current hosted address restored login.

The shared recharge page also stalled on desktop because its main-process configuration provider called a renderer-only storage adapter and waited for an unanswered IPC response. Main and renderer now share a pure address policy, with each process reading its own storage. Recharge, balance, order, and credit-application requests use a shared authenticated client with a 15-second deadline covering address lookup, authentication, and response parsing; loading failures offer retry. Payment polling, continuation, and cancellation also use the shared authentication path.

Desktop authentication and managed-runtime refresh use Chromium networking, matching SMS requests' system proxy and certificate handling. Login validates identity before persistence and distinguishes transport, timeout, response, and local-setup failures without logging credentials.

Validation includes reproduction of the recharge IPC deadlock and the separate proxy-only login failure in the signed 0.2.24 app, migration and session-restore regressions, shared account request deadlines, recharge loading/retry tests, and desktop/WebUI test suites. Payment requests are tested against isolated fixtures; no real payment is made.
