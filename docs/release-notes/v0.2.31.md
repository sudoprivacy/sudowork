# Sudowork v0.2.31 Release Notes

Since v0.2.30: 26 commits excluding merges, comprising four features, 15 fixes,
six test changes and one release preparation change.

## Features

### Shared cloud browser sessions

- Desktop cloud conversations and WebUI use the same browser panel and
  authenticated viewer tab. AI and users operate the same browser, profile and
  selected tab.
- Page and native window views support headless automation and headful Chrome.
  Viewers attach on demand; automation retains the persistent profile when the
  panel closes.
- Take control blocks AI browser writes and drains current operations. Return
  to AI carries the user's note and a fresh browser observation. A disconnected
  viewer does not silently return control.
- Start, Stop and confirmed Restart expose actual extension/CDP and
  headless/headful capabilities. Restart retains the profile and login cookies;
  stale input cannot reach the replacement browser.
- Native file chooser uploads and completed downloads use authenticated session
  routes. Transfers check session ownership, operation epochs, file size and
  SHA-256; a previous chooser cannot attach files to a changed tab.
- The public ai-dev-browser dependency is pinned to v0.56.0. Desktop bundles the
  published scode v0.2.30 runtime, including HTTP MCP and native image support.

### Installed agents

- Installed template cards can start conversations using stable template
  identities and open the latest session.
- Catalogue entries and account caches are shared across conversation views.

## Fixes

- Personal agents retain cloud execution and the owner's selected model.
  Managed conversation reloads restore the owner's model, organization and
  authorized history.
- Shared history follows the current agent and account; changing context resets
  cached drafts. Restored idle conversations keep accurate processing state.
- Cloud model selection refreshes after cancellation.
- Artifact messages load correctly after browser handoff and conversation
  reload. A first browser return in a fresh conversation attaches its stream
  before starting the AI turn.
- The shared cancel button has an accessible name.
- Browser startup consumes the verified IPv4 readiness fix. Binary uploads send
  one content type instead of merging JSON and binary headers.

## Validation

- Local root suite: 3,171 passed, 30 existing skips. Windows WebUI: 387 passed;
  the Linux deployment suite runs in CI.
- All 31 applicable checks passed on the final files PR, including Linux and
  Windows browser backend tests, native runtime checks, builds and type checks.
- Real API WebUI journeys ran against the published scode v0.2.30 artifact and
  actual Chrome: headful handoff, trusted page submission, reload, lifecycle
  changes, persistent cookies, native uploads and verified downloads.
- Browser lifecycle and file journeys are committed as opt-in live tests.
  Provider/header, owner authorization and stale-operation checks protect
  regression in CI.

## Delivery scope

Cloud browser availability requires a configured managed browser backend in
Moss. Production rollout and account acceptance are tracked separately from
publication of these application artifacts. Local Desktop handoff, optional
local Chrome pairing and physical phone acceptance remain separate work.
