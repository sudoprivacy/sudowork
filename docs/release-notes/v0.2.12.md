# Sudowork v0.2.12 Release Note

> 自 v0.2.11 起累计 6 个提交（feat 1 / fix 2 / refactor 1 / test 1 / docs 1）。本版本为小步迭代，聚焦**可观测性（Sudo Log 遥测镜像）**、助手技能选择修复，以及 ACP 模型切换路径的收敛。

## 重点新功能

### 可观测性 / 遥测

- 遥测与崩溃事件镜像上报 Sudo Log 后端：新增 `SudoLogTelemetryReporter`（约 600 行，含批量上报、重试），`TelemetryBatchReporter` 与 `CrashReporter` 接入镜像通道，事件双写不影响原有上报链路（含 170+ 行单测覆盖）

## 重要修复

- **助手（Assistant）**：修复导入的技能选择无法正确匹配的问题 —— 技能选择匹配逻辑收敛到 `assistantSkillSelection`（别名/导入技能归一化），`AgentModalContent` 与 `AssistantEditDrawer` 复用同一匹配路径
- **遥测**：归一化 Sudo Log 上报的 environment 字段，避免环境标识不一致导致后端数据分裂

## 工程重构（无功能变更）

- **ACP / scode 模型切换**：移除 scode 模型切换失败后的进程重启兜底。`session/set_model` live RPC 现在是模型切换的唯一权威路径（SSOT）——scode 侧在原会话内就地重建 runtime（模型 + 认证模式），`setModel` 已内置断线重连，剩余失败即真实切换错误，直接上抛而不再重启引擎。连接恢复保留独立路径（Restart & Connect），会话恢复（`session/load`）保证切换不丢上下文

## 测试

- E2E 新增 `paste_clipboard_image_file` op（ClipboardEvent + DataTransfer 从 CDP 注入粘贴事件）与 `assert_not_contains` 负向断言 op；补齐 `acp-image-vlm-fallback` 用例（28 步，覆盖原生透传 / 预检降采样 / VLM 路由三阶段），回归守护「scode 声明 autoHandlesWrongModel 时不得弹出模型不支持图片提示」
